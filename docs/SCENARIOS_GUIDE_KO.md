# 시험 시나리오와 기대 정책

이 문서는 S01 구현 후보의 사용 안내입니다. 구현·검증·커밋 상태의 정본은 `IMPLEMENTATION_CAMPAIGN.md`와 단계별 검증 기록입니다.

## 목적과 위치

`실험실 구성 → 트래픽 프로파일`에서 기존 엔진 템플릿과 시험 시나리오를 관리합니다. 시나리오는 '어떤 대상에 어떤 정책을 기대하며, 어떤 증거로 판단할 것인가'를 기록합니다.

시나리오를 저장해도 실행 승인, 패킷 전송, MCP 연결, 모델 호출 또는 계측이 시작되지 않습니다. 기록한 장비 버전·한도·자산 식별자는 운영자의 선언이며 실측·안전 검증 결과가 아닙니다.

## 생성

1. `시험 대상`에서 DUT와 SINK를 각각 등록합니다. 등록은 대상에 대한 시험 허가가 아닙니다.
2. `트래픽 프로파일`의 시나리오 영역에서 `새 시나리오`를 엽니다.
3. 이름, 목표, DUT/SINK, 장비·정책 버전, 프로필과 프로토콜·IP 버전을 지정합니다.
4. 기대 동작, 전달 기준과 탐지 요구를 입력합니다.
5. 송신 예산, 정상 서비스·장비 자원 중단 조건 및 필요한 증거를 명시합니다.
6. 저장한 시나리오의 버전, 대상 snapshot과 digest를 확인합니다.

숫자 입력은 명시적인 정수입니다. 화면에서 허용하는 최대값은 데이터 표현 한도이지 해당 DUT에 안전한 시험량이 아닙니다. 실제 실행 단계에서는 장비 capability, 승인 범위, 독립 안전 제한이 추가로 필요합니다.

## 기대 동작의 의미

- ALLOW: 전달되어야 하는 트래픽입니다. 최소 전달률과 정상 서비스 조건을 명시합니다.
- BLOCK: 차단되어야 하는 트래픽입니다. 최대 허용 전달률을 명시합니다.
- ALERT: 탐지 이벤트가 필수입니다. 트래픽은 허용할지 차단할지 전달 기대값을 별도로 선택합니다.
- 탐지를 요구하면 탐지 제한 시간과 DUT 이벤트 증거가 필요합니다.

이 값들은 측정 결과가 아닙니다. 아직 수집하지 않은 자료를 0이나 정상 상태로 표시하거나, 기대값 자체를 PASS로 해석하지 않습니다.

## 프로필과 자산

- 패킷 재생 시나리오는 TCP/UDP/DNS와 앞단·뒷단 PCAP 증거를 사용합니다.
- HTTP 시나리오는 HTTP 프로필과 정상 서비스 관측을 사용합니다.
- 수동 캡처 템플릿은 트래픽 발생 시나리오로 선택하지 않습니다.
- 모든 시나리오는 정상 서비스 프로브 증거가 필요합니다. 자원 중단 조건을 지정하면 자원 메트릭 증거도 필요합니다.
- PCAP 메타데이터를 기록하는 경우 이름, SHA256, 바이트 크기만 저장합니다. 파일을 업로드하거나 읽거나 재생하지 않습니다. 메타데이터가 없거나 아직 검증되지 않았다는 사실을 실제 실행 가능 상태와 구분해야 합니다.

## 수정과 이력

수정은 기존 레코드를 덮어쓰는 대신 새 버전을 추가합니다. 과거 버전에는 당시 DUT/SINK와 프로필 snapshot, 정책·장비 버전, 조건과 digest가 남습니다. 하나의 시나리오는 최대 10개 버전, 로컬 레지스트리는 최대 100개 시나리오를 보관합니다.

과거 버전은 현재 대상 목록에 의존하여 다시 작성되지 않습니다. 이후 실행 기능은 시나리오 ID뿐 아니라 버전과 digest까지 고정해야 합니다. 이름이 같아도 ID가 다르면 별도 시나리오입니다.

Digest는 저장된 내용의 일관성을 확인하는 값이지, 운영자 신원이나 악의적인 로컬 파일 변경을 막는 전자서명이 아닙니다.

## 저장 충돌과 통신 오류

다른 화면에서 먼저 저장하면 현재 편집본의 revision이 오래되어 저장이 거절될 수 있습니다. 또한 응답 유실은 저장 실패와 다릅니다. 서버가 저장했지만 브라우저가 확인하지 못했을 수 있습니다.

이 경우 입력을 보존하고 추가 저장을 잠급니다. 명시적으로 다시 조회하여 이력을 확인하고, 필요하면 기존 입력을 복사하거나 검토한 뒤 최신 상태에서 새 편집을 시작하세요. 재조회는 저장 요청을 자동으로 다시 보내지 않습니다. 대화상자를 닫는 것도 이미 서버로 전송된 저장 요청을 취소한다는 뜻이 아닙니다.

단, 저장 요청이 `SCENARIO_STATE_UNAVAILABLE` 또는 `SCENARIO_COMMIT_UNCERTAIN`으로 끝나면 저장소 오류에 대한 별도 차단이 유지됩니다. 이때 GET 재시도·닫기·초안 버리기로 새 생성/수정/저장을 다시 허용하지 않습니다. 이력 조회와 초안 검토·복사는 가능합니다. 페이지 새로고침도 서버 차단을 해제하는 복구 명령이 아닙니다.

실패 자료는 한도 내 보존하고 추가 저장을 거절합니다. 유효한 CLEAN 기록·저장본·빈 대기 영역을 확인한 새 API 프로세스는 정상 재개할 수 있습니다. 그 밖에는 모든 쓰기 프로세스를 멈춘 뒤 명시적으로 검사·보관·복구해야 합니다. 불완전한 자료는 현재 유효 저장본을 유지하는 `--accept-current` 결정으로만 수용할 수 있습니다. 정확한 명령, archive 한도, 일회용 시작 ticket과 중단 후 재개 절차는 [시나리오 저장소 복구 안내](SCENARIO_STORAGE_RECOVERY.md)를 따르세요. 실패 요청 자동 재전송이나 잔여 파일 삭제는 하지 않습니다.

## 저장소와 제한

시나리오는 현재 초안 저장 파일 이름에 `.scenarios.json`을 붙인 별도 로컬 파일에 저장됩니다. 기존 대상·캠페인·AI 프로필 파일은 변경하지 않습니다. 단일 프로세스 개발용 저장이며 운영 인증이나 다중 프로세스 실행 DB를 대신하지 않습니다.

손상된 레지스트리는 빈 목록으로 덮어쓰지 않습니다. 원본을 보존하고 복구해야 합니다. 파일 안에 실제 자격 증명, 실행 명령, 파일 시스템 경로나 원격 자산 URL을 넣지 마세요.
