# 개발용 LAN 접근 옵션

기본값은 루프백 전용입니다. 브라우저가 서버의 사설 IP에 HTTP로 접속하는
개발 환경에서는 아래 두 설정으로 **접속 제한만 명시적으로 완화**할 수 있습니다.
인증·TLS를 제공하는 기능이 아니므로 신뢰하는 격리망에서만 사용하세요.
인터넷 공개나 여러 사용자의 권한 분리에 적합하지 않습니다.

## 서버 10.0.0.2 / 브라우저 PC 10.0.0.1 예시

웹 포트가 5173인 경우, 서버에서 기존 API 시작 명령에 다음 환경 변수를 추가합니다.
기존 상태 파일 경로와 DB/socket 설정은 그대로 유지합니다. 저장소 루트에서
`make api`를 사용하던 경우의 예시는 다음과 같습니다.

```sh
DDOSPECTOR_ALLOW_INSECURE_DEV=1 \
DDOSPECTOR_DEV_ORIGIN=http://10.0.0.2:5173 \
make api
```

API는 그대로 127.0.0.1:5180에 두고, 별도 터미널에서 웹만 서버 LAN 주소에 바인딩합니다.
`make web`의 고정 localhost 옵션을 중복 전달하지 않고 Vite에 직접 지정합니다.

```sh
cd web
node node_modules/vite/bin/vite.js --host 10.0.0.2 --port 5173 --strictPort
```

10.0.0.1의 브라우저에서 `http://10.0.0.2:5173/ai-settings`를 엽니다.
서버의 해당 주소/포트에 접근 가능한지는 실제 네트워크·방화벽 설정에 달려 있습니다.
이 기능은 바인딩·방화벽·기존 서비스를 자동 변경하지 않습니다. 변경한 환경 변수는
API 프로세스를 다시 시작해야 적용되고, 웹은 최신 코드로 실행/빌드되어야 합니다.

`DEV_ORIGIN`은 접속 PC의 IP가 아니라 **브라우저 주소창의 웹 Origin**입니다.
프로토콜, 호스트, 포트를 정확히 지정하며 끝의 `/`, 경로, 사용자 정보, query,
fragment, wildcard는 허용하지 않습니다. HTTPS와 DNS 이름, 대괄호 IPv6도 지원합니다.
이 옵션은 명시적인 비기본 개발 포트(예: HTTP 5173, HTTPS 8443)용입니다.
브라우저 Origin에서 생략되는 HTTP 80/HTTPS 443 포트는 시작 시 거절합니다.
웹 포트를 바꿨다면 설정값도 함께 바꿉니다. Vite는 기본적으로 `/api`를 로컬 API로
프록시하며 Host를 보존합니다. 커스텀 프록시를 사용하는 경우 전달되는 Host/Origin이
이 정책과 일치해야 합니다. 외부 API 포트까지 자동으로 허용하는 설정이 아닙니다.

## 옵션 계약

- `DDOSPECTOR_ALLOW_INSECURE_DEV=1`: 추가 Origin과 그 정확한 Host authority를 허용.
- 미지정, 빈 값, `0`: 원래 루프백 정책. 이때 `DEV_ORIGIN`은 무시됩니다.
- 다른 flag 값 또는 활성 상태의 잘못된 Origin: 상태 저장소 생성 전에 시작 실패.
- `DDOSPECTOR_DEV_ORIGIN`: 하나의 정확한 추가 Origin. 다른 Host/Origin은 계속 거절.
- 기존 규칙대로 `AIDDOS_` 이름은 호환 별칭이며 `DDOSPECTOR_` 값이 우선합니다.
- 설정은 앱 생성 때 고정되고 활성화 경고가 출력됩니다. 요청마다 바뀌지 않습니다.
- 이 기능에는 인증이 없습니다. 허용된 주소에 접근하는 비브라우저 클라이언트도
  초안과 설정을 변경할 수 있습니다. Host/Origin 검사를 인증으로 간주하지 마세요.

`DDOSPECTOR_ALLOW_INSECURE_DEV=0`으로 API를 다시 시작하면 원래 제한으로 돌아갑니다.
포트가 이미 사용 중이면 기존 프로세스를 임의 종료하지 마세요.

## 바뀌지 않는 제한

본문 크기/프레임/수신 기한, 중복 헤더/JSON, 스키마 검증, 저장 충돌,
도구의 정확한 별도 승인, 모델 엔드포인트의 루프백 제한, LIVE/MCP 실행 거절은 유지합니다.
`LIVE execution locked`는 계속 표시됩니다. PG/모델/DUT 시험을 승인하거나 실행하지 않습니다.
기존 workspace의 정적 deployment 메타데이터는 이 시작 옵션의 상태 표시가 아닙니다.

HTTP에서는 `crypto.randomUUID()`가 없어도 `crypto.getRandomValues()`로 UUID v4를
생성합니다. 프로필·대화·승인·OFFLINE 요청·증거 등록에서 같은 함수를 사용하며
`Math.random()` 같은 약한 난수로 대체하지 않습니다. UUID 생성이 가능하다고 해서
HTTP 통신이 암호화되거나 연결된 모델의 작동이 검증된 것은 아닙니다.

`crypto.subtle`이 없는 HTTP 환경에서도 시나리오·승인 텍스트·증거의 SHA-256
검증은 생략하지 않습니다. 동일한 표준 SHA-256을 로컬에서 계산하며 보안 컨텍스트에서는
기존 Web Crypto 경로를 우선 사용합니다. 외부 해시 서비스나 추가 패키지는 필요 없습니다.
