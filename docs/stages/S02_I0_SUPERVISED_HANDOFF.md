## 2. State and entrypoints

Resource custody retains `NEW/PENDING/OWNED/BLOCKED/COLLISION/CLEAN`, successful create receipt, exact ID/name/independent labels, created timestamps, cidfile and sole volume linkage (source 455–626,703–745). It is **not** the work state.

Work state is `ELIGIBLE`, `PENDING`, or absorbing `REVOKED`. Unknown/missing state denies. Initialization is not eligible before successful original-owner construction and OWNED custody. Cleanup invocation permanently closes work admission. `work_failed` remains a compatibility projection of terminal work revocation, never the sole authority. `ready` becomes true only at the successful outer bootstrap commit.

One original owner retains one current attempt, no queue. Its states are `RESERVED → SPAWNED → GRANTED → SETTLING → SUCCEEDED`, or `FAILED/UNCONFIRMED`. Failure/unknown revokes the owner; SUCCEEDED permits only a **different new** attempt. Do not replay, rearm, reconstruct an owner from journal, retry a consumed grant, or clear failure after revalidation/late success. Remove mmap/work.fence from new work admission; do not delete historical files. The old mmap seams are **ELIMINATED**, not fault-fired GREEN.

## 3. Exact grant, identity and deadlines

Use one anonymous **Popen stdin PIPE**, binary/unbuffered parent streams, plus the existing stdout/stderr PIPEs; `close_fds=True`, `start_new_session=True`, no pass_fds, environment grant or filesystem token. The actual Python3.12.13 stdlib `_get_handles` creates stdin PIPE at lines1697–1703; the retained source and native feasibility show this works. Generic `communicate()` buffers arbitrary output, so the granted branch must use bounded nonblocking `select`/`os.read`/`os.write`, not length-check after communicate.

The owner chooses D **once**, from the existing timeout at the PG sub-attempt boundary, before its custody/argument/pipe preparation. Public probe: entry + timeout (default10s). Bootstrap setup: private setup entry +25s (source659), covering its final outer ready publication too; earlier startup retains its existing15s readiness clock and command timeouts, not a new reset of setup D. Restart retains existing per-command10s/stop5s bounds. No new aggregate bootstrap/restart promise is made. Every child wait, frame write/read, source/custody validation, connect/SQL admission, result processing and success tail checks the same D and never grants a fresh business grace. Child readiness retries retain their8s maximum additionally capped by D. Recheck after each fallible/waiting boundary and immediately before each new connect/SQL and final success. Ordinary OS preemption after a check cannot be made atomic with external effects.

Supervised argv is the existing interpreter/file/`--pg-child DIR --action A` plus `--i0-attempt N --i0-deadline-ns D`. N and D are canonical positive decimal uint64 (at most20 characters, no signs/leading zeros). They are nonsecret bindings, **not** authority. Missing bindings refuse before reading stdin. Verify stdin is a pipe; read one frame then EOF by D, retaining at most162 bytes. Never accept a second frame or trailing whitespace. No fallback to env, journal success, work.fence, regular-file stdin or a new token after parse failure.

Exact network-order struct: `!8sIQ16sIQ32s32sQ32sBQ` = **161 bytes**:

| In order | Size / meaning |
|---|---|
| magic | 8: `I0GRNT1\0` |
| owner PID, start ticks, boot UUID | 4,8,16; exact original owner, not a reconstructed object |
| child PID, start ticks | 4,8; exact newly returned Popen; same boot UUID |
| source SHA256 | 32 raw bytes of the executing harness source |
| custody commitment | 32 raw SHA256 of compact sorted UTF-8 JSON below |
| attempt N | 8; owner-local uint64 monotonic sequence, never reset/reused |
| nonce | 32 cryptographically random bytes, private to this one attempt |
| action | 1: setup=1, write=2, read=3 |
| deadline D | 8: original host monotonic nanoseconds |

Custody commitment input is exactly `{directory,owner_process,source_sha256,name,labels,socket,cid,created,volume,receipt}`: canonical resolved directory; original initialized PID/start_ticks/boot_id; source lowercase64hex; exact initialized name/labels/socket; registered cid/Created/volume; exact create receipt `{code,stdout,stderr,timed_out}`. Use UTF-8, sorted keys, compact separators, ensure_ascii=False, allow_nan=False; retain scalar/string representations from the existing source. Owner verifies custody before issuing the grant. Child validates matching initialized/registered/create-result records, cidfile, socket mode/ancestor/UID and this commitment; performs the existing exact read-only resource metadata validation via a custody-only inspector, **not** an eligible reconstructed Harness. Grant stays private and PENDING spans these reads and their finalizers. Existing whole-journal validation is not newly asserted memory-bounded.

Before grant, parent binds Popen PID/start/boot, source and original owner identity; no grant on unknown identity. Child verifies own PID/start/boot, live non-zombie direct parent `getppid()` against original initialized owner PID/start/boot, argv action/N/D, current source hash, custody commitment and unexpired D. Same-UID hostile fabrication is outside this contract, not cryptographic authentication of an adversarial local process. Parent/source/custody checks and private single-consumption flag are repeated at supported child action checkpoints; old N/nonce or a frame for another child cannot establish an attempt. A failed check cannot be retried into success.

Missing, malformed magic/size, truncated, >161 bytes, trailing/replayed frame, wrong owner/boot/start/child/action/source/custody/N/D, stale deadline, read error or EOF before complete frame: no new PG I/O, child exit78, no success proof. If enrolled, the original supervisor revokes on that outcome even if child cannot write any diagnostic. An unadmitted raw refusal cannot poison another owner. GO write/close failure may have delivered bytes: revoke and settle, **never** infer zero effects or accept a late successful child.

## 4. Complete outcome and cleanup

After a validated grant the child consumes it once for one fixed action. Child exceptions in endpoint acquisition/import/identity/custody reads/connect/SQL/PG context close/stream close/result encoding/output are enrolled failures. Required finalizers must finish before success proof. For an enrolled child, parent success requires **all**: exit0, no latched timeout/failure, actual reap, all three parent pipe dispositions proved with one close attempt each, exact proof binding/shape, required existing observer/`pg_child_exit`/`pg_proof` and outer ready/restarted publications, all helper/context/ContextVar restoration, final fallible tail and last D check. Prepare the returned object before the final state stores; no fallible mechanism work after making ELIGIBLE. An apparently successful journal/proof before that commit is diagnostic history, never admission authority.

Any acquisition/body/publication/finalizer error or unknown outcome keeps PENDING/default-deny and latches REVOKED before fallible diagnostics; no post-failure write is required. A caught local primary keeps the same object/type/message; cleanup adds a bounded secondary classification without replacing it. Child exceptions retain sanitized type/site classification, not exception text/SQL/credentials. Nonzero/timeout gives existing parent `PG_PROBE_FAILED`; diagnostic failure cannot turn it into success. Required success publication failure is failure even after child exit0. Do not publish an accepted terminal event that readers could use to clear a memory failure.

The Popen custody boundary must enclose post-spawn registration, wrapper construction, observer and ContextVar reset, not begin after them. Keep the exact returned process/streams until actually retired. On failure latch before signaling; kill only the proved exact own process/group and reap independently of output reads. Existing retirement observations retain at most2s drain and, when necessary, at most2s independent fallback wait; neither extends D or grants work. Close each acquired pipe once even when wait/read/another close fails. Do not retry ambiguous numeric FD close. Unknown wait/FD disposition is UNCONFIRMED, never CLEAN; save before-rescue identity/exit/FD evidence. Cleanup-only failure is still failure.

Work refusal does not erase successful create receipt or resource cleanup authority. Once child disposal is proved, the original owner can use its existing separate30s cleanup path despite REVOKED. It must revalidate exact receipt/ID/name/labels/cidfile/Created, volume Name+CreatedAt and sole linkage; after container removal verify exact absence and no foreign volume attachments, then remove that volume and verify exact absence. Custody mismatch/required evidence loss or still-unconfirmed child disposal prevents destructive cleanup and retains evidence; no adoption, name-only deletion, prune or automatic new owner. R03's independent retirement acceptance remains mandatory. Parent death before GO denies; after GO, the next schedulable checkpoint denies. Already-issued SQL can complete and orphan cleanup is not guaranteed.

## 5. Engineering bounds, not a new business quota

One current owner attempt; zero queue, extra threads or per-attempt persistent authority files. Its control representation is exactly87 bytes, struct `!QBQ32sIQ16sBBiBBH`: N, action, D, grant digest, child PID/start/boot, phase, exit-known flag, signed exit code, closed-pipe mask, unknown-pipe mask, first-failure code. Control actions1/2/3 are setup/write/read (bootstrap's one private setup uses1); restart=4 and fixture module/class/AF_UNIX admissions=5/6/7. Only1..3 may appear in a wire grant. D=0 means no PG-child deadline yet/not a PG-child operation, never an acceptable grant. Local admissions keep existing connector timeouts, not a new lifetime/watchdog guarantee, and must finish their validation/connector/finalizer tail before eligibility; no child exit/pipe witness is fabricated for a non-child operation. Before spawn the child fields/digest are zero and exit-known=0; phase codes RESERVED=0, SPAWNED=1, GRANTED=2, SETTLING=3, SUCCEEDED=4, FAILED=5, UNCONFIRMED=6; masks use stdin/stdout/stderr bits0/1/2 only. Failure codes are NONE=0, PREPARATION=1, SPAWN=2, IDENTITY=3, GRANT=4, CUSTODY=5, BODY=6, FINALIZER=7, PROOF=8, PUBLICATION=9, DEADLINE=10, RETIREMENT=11, INTERRUPTED=12, UNKNOWN=13; retain the first, with secondary disposal represented by flags rather than a growing list. Runtime wrappers may hold those fixed fields instead of repeatedly serializing them; the logical representation, not Python object overhead, is bounded. Add one161-byte private grant while handing off, one Popen and at most three parent pipe wrappers. Use the same record for terminal failure; no history map, retained traceback chain, token cache or accumulating Process objects. After full success retain only the owner identity/source binding and uint64 high-water N; prior proof is returned to its caller and required old journal evidence remains. Uint64 overflow refuses before another launch, never wraps; this is a wire-representation guard, **not** the rejected128-operation policy. Cleanup consumes no work sequence quota.

Granted stdout is exactly compact UTF-8 `{grant_sha256,proof}` plus one newline. Grant hash is a nonsecret receipt commitment, not the nonce. `proof` has exactly the15 existing keys at source986–1002 and their action-dependent PG invariants: PG16/durability/roles/owner/socket settings/DDL denial/AF_UNIX/app-schema absence/marker and cap behavior unchanged. Validate strict bool/int/null and exact arrays; no arbitrary keys. Provenance `module/interpreter/prefix` are absolute strings, each <=4096 UTF-8 bytes, and driver is printable ASCII <=256 bytes. Three maximally JSON-escaped4096-byte paths plus the fixed schema and256-byte version fit **81920 bytes**, including envelope/newline (source-derived sizing in `implementation-evidence/schema-bounds.json`). Oversized values fail rather than truncate. These limits concern metadata encoding, not PG operations.

Stderr retains existing closed `{blocked,site}` shape: identifier <=64 ASCII bytes, at most16 `[function,line]` pairs, function <=64 ASCII bytes and positive uint32 line; total <=4096 UTF-8 bytes including newline. Do not truncate a deeper diagnostic into apparent completeness: an unrepresentable diagnostic is publication failure with no success. Never log nonce, raw grant, SQL, environment values or driver exception strings.

Parent buffers at most stdout81920 + stderr4096 bytes; read at most `min(4096, remaining+1)` and reject the one-byte overflow **before appending**. Child input buffer <=162 bytes; raw frame decode only at exact161+EOF. At most one bounded decoded proof and one encoded representation during validation/publication; release transport arrays after settlement. These are logical buffers, not a CPython heap/RSS bound. Three kernel pipes have finite host-reported capacities, recorded with F_GETPIPE_SZ; do not increase them. Native feasibility observed65536 each. No claim that default kernel capacity is a portable fixed constant.

**Persistent retention is deliberately unchanged:** no new START/TERMINAL authority log is required; PENDING is memory-owned. Existing child_started/reaped/pg_child_exit/pg_proof and custody journals are still append-only evidence. The new grant/nonces/control history are not appended; a nonsecret grant digest may accompany the existing proof. There is a per-attempt output bound, **not a whole-journal lifetime disk cap**. Source394–419 already appends without a lifetime cap, and validation609/762 reads history. No deletion, rotation, truncation, old-evidence suppression, whole-journal reservation or new admission count policy is authorized. Any later demand for a globally bounded historical journal requires an explicit preservation policy decision; stop rather than invent it. This draft claims bounded new transport/live control retention only.
